# Contributing to LGP

Contributions are welcome.

LGP is intentionally early. Challenge the model, terminology, semantics, and interoperability assumptions.

## Good Contributions

- identify ambiguous Core semantics;
- propose a smaller interoperable contract;
- describe a concrete provider or consumer implementation experience;
- propose test vectors;
- identify portability issues;
- identify security or privacy concerns;
- propose transport bindings without coupling them to Core;
- provide evidence that an extension belongs or does not belong in Core.

## Scope Discipline

LGP specifies observable Logical Gate behavior.

Please avoid proposals that require a specific provider algorithm, implementation technique, database, runtime, or commercial implementation.

## RFC Process

For substantial changes:

1. open an issue describing the problem;
2. discuss alternatives and interoperability impact;
3. create a numbered RFC draft when the change is large enough;
4. obtain review;
5. merge only after the protocol impact is understood.

Small editorial fixes can be submitted directly.
